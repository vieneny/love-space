# 第一版产品和技术说明

## 已确认方向

用户经营一个情侣记录产品，多个互不相见的双人空间共用服务。当前先使用个人主体体验；后续商用资格、服务类目和支付在实际经营前单独确认。不是向不同商家售卖的独立品牌 SaaS。

核心路径是「创建旅行 → 按实际发生日期记录地点/故事/照片 → 地图和时间线回看」。可以补录国内外旅行，同一地点多次到访保留多条日期记录；重要事件可以没有地点。不会后台采集持续位置或生成所谓 GPS 轨迹。

第一版包括地图/时间线、旅行分组、私密/共享手记、图片、双人邀请、纪念日、心愿、每日问答、心情、习惯打卡和反馈。公开社区、陌生人匹配、实时定位、聊天、支付、AI 和营销分销不在第一版范围。

## 技术栈

| 层 | 当前选择 | 职责 |
| --- | --- | --- |
| 小程序 | uni-app 3.0.0-5020620260917001 / Vue 3.4.21 / TypeScript | 编译微信小程序，H5用于本地交互预览 |
| 管理后台 | Vue 3.5 / Vite 7 / TypeScript / Element Plus | 运营统计、元数据、题库、反馈和审计 |
| 后端 | Python 3.12 / FastAPI / Pydantic | 微信登录、权限、记录、私有图片和管理 API |
| 数据层 | SQLAlchemy 2 / Alembic / PostgreSQL 17 | 数据访问和可持续迁移；本地允许 SQLite |
| 身份 | 微信 jscode2session / JWT / Argon2 | 客户端不保存 AppSecret，管理员令牌与用户令牌隔离 |
| 存储 | 受鉴权保护的媒体目录，生产使用持久卷 | 禁止公开图片静态目录；后续可接私有对象存储 |
| 地图 | 微信原生 map / 腾讯地图体系 | 手动标点；地图与时间线读取同一条回忆 |
| 工程 | pnpm 11 workspace / uv / Git | 同仓库维护三端、锁版本、生成 OpenAPI 类型 |
| 备用部署 | Docker Compose / Caddy | 单机合并 API、后台、数据库，自动 HTTPS |

「一套代码」指同仓库和统一后端/契约。管理后台与小程序的交互场景不同，分别维护界面，不强行用同一页面。前后端通过 JSON API 分离；微信端对不支持的 PATCH 使用限定的 POST 方法覆盖，服务端仍执行正常认证和权限校验。

## 多空间与隐私

一个账号同时只能加入一个有效双人空间，最多两位成员。共享记录必须属于当前空间；仅自己可见的记录始终由作者访问。管理员读取运营所需元数据，不读取私密故事、坐标或照片。

解绑关闭旧空间，撤销双方关系与旧图片访问；作者保留自己的内容。新关系创建新空间，旧内容不能自动进入新关系。以后若要升级真正的商家多租户，需另加商家配置、管理员角色、独立计费/品牌和域名体系，不能只给现有空间改名。

## 全球地图边界

保留国家/城市、原始经纬度、GCJ-02/WGS84、地点时区，以及日期精度；不把上传日期当作事件日期。国内 GPS 坐标不会盲目当作国内地图坐标；尚未验证的国内 WGS84 点位保留在时间线。跨180度经线的地点顺序线分段处理。

H5当前是带明确说明的坐标分布网格，不是完整地图服务。微信端编译为原生地图；上海、东京、首尔、纽约、悉尼的真实底图、坐标对齐和真机交互尚待正式 AppID/授权后验收。地点搜索/逆地理编码和腾讯海外商业服务目前未开通，不将存储海外坐标描述为海外服务已验证。

## 后续演进

先完成两人实际体验与数据备份，再补限流、分页、导出/注销、异常监控、对象存储、订阅通知和正式隐私条款。规模扩大后再拆数据库与任务服务，避免首期购买闲置资源。正式对公众运营前需要验证类目、备案、隐私声明、真实微信登录、持久化存储与恢复能力。
